`;; Also: COUT (A2RM78)`: hover shows the document, and the lint reports a key that is not in this table. See
[DocComments.md](DocComments.md) (section 2.4).

The language server reads this table from the SDK's copy of this file. A `Bibliography.md` at the root of a
workspace adds documents of its own, or replaces a key, with the same columns.

## How the Apple Pascal documents were checked

The interpreter's names (`src/Retrocore.Pascal/Sdk/Interpreter/1.1`) were checked against the SDK's build of
SYSTEM.APPLE, which is byte-identical to Apple Pascal 1.1's. The full method, with the counts, is in
[`docs/conversions/PascalInterpreter.md`](conversions/PascalInterpreter.md).

- **WK11:** the PDF's text layer, a typed listing with addresses and bytes. A code label is cited where its address
  column gives it at the address the build gives the definition (Initialize, which Kusche lists where it is loaded,
  `$F29C`-`$F674`, mapped to where Restart copies it to run, `$6827`-`$6BFF`); a name for a byte in zero page or memory is cited where Kusche's
  instruction and ours at the same address use it and our symbol, decoded from the instruction's bytes. His
  generated names (the sequential `INTxx` ... `INZxx`, `A` and an address, his macros' locals) are not cited.
- **A2PBIOS:** its excerpts of Apple's BIOS source, matched to the build instruction for instruction, and its
  equates by address. A name found only in prose is not cited.
- **A2POSRM:** the Internet Archive's OCR text, and the scan's pages where the OCR is illegible. P-codes and
  standard procedures by their numbers (its table misprints five standard procedures' numbers; the names are cited
  at the numbers `Pcode.asm` and the build agree on), registers, SYSCOM's and the mark stack's fields and the
  execution errors by what it says each is.
- **UCSD20:** the OCR text. SYSCOMREC's offsets computed from its declaration (identifier lists allocated
  backward, as its own comment says); the Compiler's p-code and standard-procedure comments by their numbers.
- **UCSD20IO:** the unit numbers, the unit I/O calls and the BIOS entry points, matched by function.

## How the BASIC documents were checked

The Microsoft 6502 BASIC keys were checked against the SDK's builds before any name is cited from them. Of their
text, only M6502's is in the repository, as `m6502.asm`. The full method, with the counts, is step 2 of the BASIC
conversion's log, [`docs/conversions/Basic.md`](conversions/Basic.md). A name is cited from a document only
where the check found that the document gives that name for that thing:

- **M6502:** the repository's `m6502.asm`. Each MACRO-10 overlay build was assembled on it, and a name is cited for a
  build where `m6502.asm` defines it and the overlay build gives it the same value as the native build. Where the
  overlay's definition is in a vendor's `.mac`, a matching value shows only that the overlay kept Microsoft's label on
  the vendor's code, so each such case was checked for the `.mac` replacing the very line that defines the name;
  M6502 is not cited on the nine rows where it does not (BASIC 4's array-creation code and BASIC 1's patch
  routines).
- **ASTIL:** names and addresses read from the "Applesoft: Internals" index, page-zero map and routine articles, and
  cited where the address equals the AppleSoft builds' value. A name found only in prose is not cited.
- **AS82:** only the archive's damaged OCR text could be read. A name is cited only where the listing's symbol tables
  give the same value as the AppleSoft builds. Apple's authorship and the date rest on the archive's description.
- **CBM4S79:** a pre-release whose addresses differ from the ROMs, so page-zero names were checked by value and code
  labels by the instructions and data at the label. It gives names for BASIC 4, and, under the lineage rule below,
  for the same definitions in the other PET builds.
- **K4S79:** assembled for RAM ($8000 lower), and cited where the address plus $8000, or the page-zero value, equals
  the BASIC 4 build's.
- **HV1, HV1R, HV2, HV4, HV4R:** assembled by a script that reads their text and reproduces each ROM's bytes but
  for the checksum bytes. A name is cited for its own build where its address or value equals the native build's,
  and, under the lineage rule below, on the same definition in the other PET builds.
  cbmsrc's notes say the reconstructions of BASIC 1 carry Commodore's later names back to BASIC 1's code, so HV1's
  and HV1R's names are the reconstructor's, not Microsoft's or Commodore's of 1977.
- **HVK4:** as the HV keys, at the BASIC 4 ROMs' addresses.
- **BV20:** assembled by a script, which puts each label where the ROMs have its code (901486-01 and the start of
  901486-06); a name is cited where its address or value equals the SDK's VIC-20 build's, and, under the lineage rule
  below, on the same definition in the PET builds, since the VIC-20's BASIC is in the PET's line.
- **KV20:** assembled by a script, which puts each label where 901486-06 has its code; a name is cited where its
  address or value equals the SDK build's. Where 901486-06 changed the listing's code, the ROM's code is what the source
  has, and the listing's names for code it removed are given in prose.
- **V20PRG and MTV:** only the archive's OCR text was searched. A name is cited where it appears beside its address,
  in decimal or hexadecimal, allowing for the OCR's damage ($ read as S, O for 0).
- **D1541:** assembled by a script; its 15,946 bytes match 325302-01 and 901229-05 at every address, so a name is
  cited where the listing puts the label at the address, or gives the constant its value. The 1540's listing
  (`DOS_1540`) is a different build from its 325303-01 chip and is not cited.
- **Lineage:** a definition that descends through a vendor's builds cites, in every build, each document of that line
  whose listing names it, including the other builds' documents; a document whose build lacks the definition stays out.
  Where a switch gives the builds different values (among them BUFPAG, BUFLEN, LINLEN, CLMWID, ROMLOC, NUMLEV, STKEND,
  CTIMR, CSTAT, CHTIM, TIL, and the error numbers the VIC-20 gives where the PET has offsets), each value cites the
  whole line, since each document names the same definition in its own build; NUMLEV's prose explains why BASIC 1's
  documents write its reserve as 23 levels. The rule and the names it reaches are recorded in
  `docs/conversions/Basic.md`, section S11.

## How the Integer BASIC documents were checked

- **IBSM:** the port's cc65 text was assembled with the repository's assembler; it reproduces the ROM's $E000-$F424
  byte for byte, so each of its names has an address. A name is cited where the port defines it at the address
  the native build gives it. The port keeps Santa-Maria's names, prefixes the Monitor's with `MON_` and adds a few
  labels of McFadden's, mostly on loops; the generic ones (`Loop12`, `Return4`) and the address labels for routines
  Santa-Maria left unnamed (`LE00C`, `TE801`) are not cited. The full method is in
  [`docs/conversions/IntegerBasic.md`](conversions/IntegerBasic.md).
- **A2RM78** for the floating-point routines, the Mini-Assembler and SWEET16: their listings in the manual, read from
  the Internet Archive's OCR text and checked label by label.

## How the Apple IIGS Firmware Reference was checked

- **IIGSFR87:** read from the Internet Archive's OCR text of the May 1987 first printing. SmartPort's error names
  (BADCMD $01 ... OFFLINE $2F, BUSERR $06) are checked against Table 7-6, and the IIgs's SHADOW ($C035), CYAREG
  ($C036), STATEREG ($C068) and HORIZCNT ($C02F) against Appendix E and its symbol table. The 3.5 controller's sources
  cite it ([`docs/conversions/Disk35.md`](conversions/Disk35.md), Q3).

## How the mouse documents were checked

- **MOUSETN:** the text of the 12-page PDF (notes #1-#7), searched in full. It gives SetMouse, ServeMouse,
  ReadMouse, ClearMouse, PosMouse, ClampMouse and InitMouse, TimeData for the AppleMouse card's $Cn1C (#2) and the
  card's GetClamp entry at $Cn1A (#7: the name is on the sample's comment for the entry, "Mouse Card firmware GetClamp
  entry"); not HomeMouse. Its MinXL ... MaxYH are the IIc's clamp holes in auxiliary memory, not the card's.
- **IICTRM89:** read from the Internet Archive's OCR text. Table 9-3 gives all eight routines at $Cn12-$Cn19, and
  Appendix D says the same calls drive the AppleMouse card in an Apple IIe. Its MouX1 and MouY1 are the IIc's soft
  switches, not screen holes. The first edition (1985) gives the same routine names for the IIc's own firmware only,
  so the mouse card's sources don't cite it ([`docs/conversions/Mouse.md`](conversions/Mouse.md), M1).
- **IIGSFR87** for the mouse: Chapter 10 says applications must use its firmware calls only if they wish to be
  compatible with the mouse in every Apple II, and Table 10-4 (Mouse firmware calls) gives SETMOUSE ... INITMOUSE at $C412-$C419, BINITENTRY,
  BASICINPUT and BASICOUTPUT at $C400, $C405 and $C407, and, as "entry points compatible with AppleMouse card",
  DIAGMOUSE, COPYRIGHT, TIMEDATA, SETVBLCNTS, OPTMOUSE and STARTTIMER at $C41A-$C41F.
